# 字幕与对话脉络 · 1.9.0

本次只调整字幕窗口的呈现、总结节奏和要点提炼；识别、翻译、云端优先与本地回退路径保持。设计按“字幕为主、总结辅助”的使用场景执行，继承原生暗色界面、系统字体与蓝色译文。

## 阅读布局

- 总结参与布局，不再盖住字幕。内容区宽度至少 760pt 时并排：左侧字幕，右侧对话脉络，各自滚动。分隔线可拖动，右栏在 300–440pt 内调整，并给字幕留出可读宽度。
- 较窄窗口通过原生“字幕／脉络”分段控件切换；右上角始终保留展开/收起入口。窗口宽度不会因打开总结自动改变，避免改写用户的尺寸偏好。
- 开启脉络时最低高度暂增至 360pt，收起恢复保存高度（字幕最低 184pt）；底边保持，避免每次切换都向上移动。窗口拖动、缩放、最小化沿用 AppKit 行为。
- 字幕维持一句原文、一句译文的分组，减少旧文本过度变暗，移除原悬浮入口占用的右侧补偿留白。控制条实际高度参与底部阅读留白；淡出不改变该高度。
- 默认展开当前更新的话题；早先话题收起，用户手动展开/收起的选择保留。广告与赞助单独收起在末尾。同一分支超过三条时先显示首条和最近两条，其余可展开。完整复制仍包含所有主题、广告和细节。
- 生成中、暂停、错误与恢复动作集中在固定底部状态区，不随正文滚出视野。点击“整理一次”可主动更新；错误后的“重试”恢复自动整理。

## 少量、连贯地更新

自动更新等待由 2 秒改为 30 秒，以首次新增内容为起点；后续字幕不会不断推迟它。首次展开已有记录、手动整理、继续及重试可以立即执行；没有新内容不发请求。繁忙时仍只保留一个最新请求，始终串行。

模型优先提炼主旨、观点、决定、分歧与进展；同一主题先筛选值得保留的观点，再合并相关来源，允许省略次要细节，禁止用分号拼接所有原句。通常每批 1–3 条，每条一般 25–70 字，结构化输出声明每条最多 96 字，总计尽量在 180 个中文字内；这些是生成约束与目标，云端接口不强制执行 JSON Schema，应用解析仍兼容旧节点容量。问候、口头语、开场铺垫和重复转述可以不生成节点。不同事件和广告仍各自独立，旧主题 ID、标题与旧事实不做整图重写。

流式输出继续在内部接收、校验，但可见脑图保留上一份完整结果，整次整理成功后一起提交；取消、截断或失败不会显示半截节点。完整字幕仍保存在本机历史中。主题及要点的物理容量限制保持。

默认空闲释放为 45 秒，以便低频整理时复用本地回退模型；折叠、暂停与内存压力仍会取消并释放本地 worker。云端正常处理不加载本地总结模型。

## 验证

- 373 项所选测试通过（13.437 秒）；最终总结指令调整后，再跑 47 项总结测试通过（2.345 秒）。全套所选测试未包含会清空共用日志的七项测试及一项依赖已安装翻译资源的测试。
- 原生截图覆盖 980、780、620、300pt 宽度、紧凑窗口的字幕切换，以及空白、整理中、暂停、错误状态；独立设计审查无须修复项。宽度 780/980pt 的实际文本边界互不重叠，宽窄切换不取消进行中的总结。
- 单次合成 1,000 条历史输入中，实时界面仍保留最多 100 条；初次显示 186.4ms，缩放 p95 15.6ms，悬停 p95 0.2ms。这是合成单次测量，未证明长时间录音、选中文字或 VoiceOver 的实际使用表现。
- 使用正式云端服务进行五阶段合成文本回放：广告、两个独立主题、回访旧主题与密集信息；8.302 秒完成，未启动本地总结 worker，旧标题、主题 ID、广告与无关主题保持。最后八条输入合成三条要点，长度分别 39/35/44 字，共 118 字，分别合并多个来源并舍弃一项细节。仍偏向提炼事实；模型没有完全遵循“单一主题最多两条”的指令，不能据此声称所有对话都会得到同样压缩效果。
- 初次回放曾把八条事实用分号拼成长节点，另一次得到四条；据此收紧筛选指令和结构声明。最终回放增加长度、总量、分号数量及多来源检查，未放宽旧主题保持与广告分离要求。
- 本地回退使用相同新指令与更短结构声明，回退路径测试通过；本次未重新运行本地真实推理。
- 1.9.0 / build 27 已安装并启动，严格代码签名验证通过，原有签名身份保持；1.8.0 保留为 `.previous` 回退副本。待发布文件与安装包中未发现配置密钥；项目和安装配置均为私有权限，安装配置位于 App 包外。
