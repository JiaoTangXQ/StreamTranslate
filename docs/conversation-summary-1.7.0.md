# 本机独立话题脑图 · 1.7.3

悬浮字幕窗右侧的 **总结** 默认折叠。首次展开后立即在本机整理多个独立话题，每个话题有自己的分支和要点；展开期间，新完成的原文字幕自动补充到对应话题。

广告/赞助、一般讨论和待归类内容分别作为独立主题。广告默认显示为折叠的紧凑行，其他主题默认展开并显示第一条分支；点击主题或分支展开、收起，顶部按钮复制文字大纲。新事件新增独立主题，回到早先话题时可以继续补充原主题；已经完成的标题和排列顺序保持不变。

自动更新只在侧栏展开且未暂停时运行。点击 **暂停** 停止生成并释放模型，**继续** 恢复更新；生成失败后点击 **重试**。无需逐次手动更新。

## 内容范围

- 输入是本次开始收音以来已完成字幕的完整原文，从本机会话归档读取，包含移出 100 条实时缓存的早期字幕；尚未完成的流式一句不参与。
- 首次生成分批处理完整会话。后续只处理新增或修正的原文，为已有脑图追加要点，不让模型重写整张图。
- 原文修正时，只撤销依赖该原文的要点，并重新处理这些要点涉及的全部原文；其他节点保留。后续决定与旧说法不同，会作为后续决定或更正补充，不改写此前标题。
- 后续变化以首次变化为起点合并等待 2 秒，持续讲话不会不断推迟该次计划。若模型仍忙，变化只覆盖一个最新待处理请求，完成当前任务后再安排处理；2 秒是调度等待，不是摘要完成时限。
- 逐步显示的完整节点属于草稿，合并在已有脑图上预览。全部批次成功后才提交脑图、覆盖条数和更新状态；取消、报错或输出被截断会丢弃草稿，保留此前完成的脑图。
- 总结只属于当前收音会话。清空记录或开始新会话会清除摘要；重启 App 后摘要不保留，原有文字历史仍可在历史窗口查看。
- AI 可能遗漏、误述或分错话题，不能保证所有广告和正文边界都判断正确。决定、数字和未定事项以原文为准。
- 最多保留 300 个话题、6,000 条要点。新增内容将超过上限时暂停更新，保留此前完成的脑图；完整字幕仍在历史记录中。

侧栏覆盖在字幕右侧，展开不重新压缩字幕的排版宽度；侧栏最大宽度为 380pt，支持 300pt 宽窗口。若窗口原高度低于 300pt，展开时暂时增高到 300pt，折叠后恢复保存的高度偏好。沿用原生深色界面。

## 增量合并规则

脑图由应用维护和合并。模型只收到本批编号原文及最多 1,200 字符的只读标签目录：主题 ID、类型、标题和分支 ID、标题，不提供旧要点正文或旧摘要。每批最多 900 个原文字符、12 条记录，超长一句拆分。模型提交新增操作，应用分配并保留节点 ID、标题与顺序。

生产推理通过 llama 的 `response_format` JSON schema 约束输出一个含 `additions` 数组的对象，最多 8 项；各节点字段必填，主题值只能是本次实际候选主题或 `new:1` 至 `new:8`，来源编号限定为本批记录。完整包验证后再提交；流式草稿扫描数组内完整对象，并处理字符串转义。旧 NDJSON 仅保留应用解析兼容和测试夹具，不是当前生产输出格式。

既有广告主题与新操作类型不符时，讨论内容不能挂在广告下面，应用用新操作提供的标题创建独立主题。每个显式新主题别名都新建独立根，即使标题和类型与旧主题相同；同批重复使用同一别名时，仍属于该批新建的同一个主题。没有全局按标题合并，避免北京和上海都叫「住房政策」时混成一题。

主题引用必须是正整数形式的 `Tn` 或 `new:n`；分支必须使用该主题既有 B 编号，或去除首尾空白后以中文起始的新名称。主题/分支标签禁止换行和 `|`，防止伪造目录条目。同一个新主题别名出现冲突标题、分支引用非法时，拒绝更新并保留此前完成的脑图。模型仍可能选错合法主题，schema 和字段校验不能证明分类或归属在语义上正确。

只有明确指向同一个既有主题 ID 和分支时，规范化后相同的要点才合并原文证据；去重保留负号和单词边界，不用删除这些字符的方式判断相同。新要点 ID 根据主题、分支、来源和文字计算确定性的 SHA-256，完整节点预览仅在大纲变化时发布；旧节点身份保持不变。

普通新增原文的 1,200 字符目录只选择有词面交集的最多 6 个主题，不用无关近期主题补位。中文使用标题/分支的双字词，英文另存每主题最多 256 个原文关键词用于检索；过滤节目、赞助等通用词，关键词不发给模型。这个保守策略减少广告被当作默认父主题的诱导；代价是普通新增记录中没有词面交集的代词或改述可能新建重复主题。它不是语义检索，不能保证分类或回访旧主题总正确。输出预算为 1,024 tokens。

生产提示词先要求依据本批原文，再列字段契约，不包含可被复制的具体 JSON 示例。

模型输出有效节点但分支名为空或仅有空白时，应用使用中性的「要点」分支；其他节点类型和来源校验仍保留。

原文修正按要点的来源关系传播：若同一要点依据多条字幕，修正其中一条会连同该要点的其他来源一起重处理，再继续追踪共享来源的依赖。应用从此前完成图的来源关系找回原主题 ID，在撤销要点后优先选入目录，即使改述后没有词面交集；仍受最多 6 个主题及 1,200 字符预算限制，不保证全部来源关联主题都入选。没有受影响的节点不重建。独立话题视图按需布局，不用单一根主题统领广告、节目正文和其他事件。

## 安装

总结使用独立的 **Qwen3-4B-Instruct-2507 Q4_K_M**，不复用语音识别或翻译模型。需要先有可运行的 llama.cpp `llama-server` 及其同目录依赖。若已安装可选 Hy-MT 运行时，在项目根目录执行：

```sh
zsh scripts/install-summary-local.sh
```

默认从 `~/Library/Application Support/StreamTranslate/HyMT/runtime/` 复制运行时。也可指定已有运行时目录：

```sh
zsh scripts/install-summary-local.sh /path/to/llama.cpp/runtime
```

脚本不编译或自动安装 llama.cpp；缺少可执行的 `llama-server` 时会停止。安装结果位于 `~/Library/Application Support/StreamTranslate/Summary/`；已有 Summary 安装先保留到同级备份目录。下载模型为 2,497,280,448 字节，另需运行时、暂存及旧安装备份空间。当前 DMG 打包脚本尚未包含此总结模型，需要单独安装；模型权重不进入 git。App 运行不依赖 Python。

## 运行与取消

总结模型按需启动，通过本机私有 Unix socket 接收文字。每次只运行一个请求，使用两个 utility 优先级 CPU 线程，关闭 GPU 计算；这项限制只适用于总结进程。CPU 推理仍会消耗内存和运算时间，长会话需要更多分段请求。

1.7.2 显式使用 `--device none --no-kv-offload --no-op-offload --no-warmup`，连同 `-ngl 0` 指定 CPU 执行并跳过启动预热。旧版只设 `-ngl 0`，没有显式禁用 KV/op offload，不能据此断言旧版完全不使用 GPU。

启动预算由 60 秒改为 90 秒，加载时显示已用秒数；启动失败、启动期间退出及超时分别显示错误类型或错误码。`AppLogger` 仅记录进程 ID、错误/退出码及耗时等元数据，不记录对话文字。启动预算不等于首次脑图的完成时限。

连续更新复用同一个模型进程，没有并行模型实例。空闲 15 秒后，即使侧栏仍展开也释放模型；之后有新原文时重新加载，没有原文变化时不再推理。

折叠、暂停、最小化字幕窗、进入仅手机显示、清空、切换收音会话、退出 App，或收到内存压力警告时取消待处理任务并释放模型。旧请求即使迟到返回，也不能覆盖新一代结果。

失败和内存压力会暂停自动更新，等待用户点击 **重试**；不会每来一句新字幕就重复启动失败任务。暂停或失败时保留此前已完成的摘要。

本机 Apple `SystemLanguageModel` CLI 探测返回 `deviceNotEligible`；本功能当前未使用 Apple Foundation Models。
