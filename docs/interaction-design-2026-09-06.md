# 以阅读为中心的交互设计

## 目标与边界

用户不是在管理模型，而是在听懂当前内容。常用路径应该从正在看的字幕出发，不要求记住菜单栏/设置的层级。简化操作不能隐去录音、权限、模型下载或未加密传输的真实状态。

本轮先交付桌面悬浮字幕的完整快捷操作闭环；手机端仍是只读输出，不新增远程开启麦克风。连接免配置与传输保密之间的产品取舍仍在，不把 HTTP 说成最终无代价方案。

## 三个层次

1. 阅读态：只保留字幕；空内容/停止/错误时给可理解的状态，不让用户面对一块黑色空窗。
2. 操作态：鼠标移动或点击字幕区域显示控制，闲置后淡出；操作按钮、展开选项、键盘聚焦时不自动消失。开始/停止、麦克风/电脑音频、自动/中文/英文、手机连接、设置、最小化就地可达。保留系统菜单作为备用，不作为常用必经入口。
3. 深层设置：模型、术语、精修、诊断和外观等低频项目留在设置。固定语言与自动模式的性能差异要解释，但不要求用户自己匹配模型。

## 切换闭环

- 空闲时选择来源/语言只改变配置，不擅自开始录音。
- 录音中切换：保存当前句/等待音频资源释放 → 更新选择 → 必要时准备兼容模型 → 恢复采集。短暂中断真实存在，不承诺无缝；字幕历史保留。
- 按钮显示切换中并阻止重复提交。停止操作取消待恢复意图，不能出现用户按停后后台自动重开麦克风。
- 权限/模型失败不冒充成功、不自动切换到另一种收音来源；保留错误和重试入口。
- 自动中英文可能需要多语模型首次下载，解释原因；固定模式不强制替换用户已选的兼容模型。

## 可用性验收

- 不打开菜单栏/设置也能选择两种收音来源和三种语言。
- 按钮有中文名称或辅助说明、选中状态、足够命中区域；窄窗不溢出。
- 鼠标停止后控制淡出，移动重新出现；展开选项/键盘操作/辅助功能下不会消失。
- 文本依然可选择复制，窗口可拖动/缩放；控制淡出不触发滚动到新位置。
- 切换不会同时启动两份采集，不丢弃已显示历史；停止优先于待恢复。
- 手机私密模式仍禁止电脑字幕和控制窗自动弹回。
- 自动化/模拟器不能替代本机权限、实际录音和使用者体验验收；结果分开记录。

## 第一轮实现与验证记录

版本 1.4.0（14）。`CaptionQuickControls` 提供阅读区域内的操作，`CaptionControlsVisibility` 管理三秒闲置隐藏；没有把原先 Settings 表单原样塞进弹窗。自动语言由设置模型兼容规则配合 ViewModel 切换流程完成。手机入口仍先打开连接界面，不绕过网络安全确认，也不偷偷启动 HTTP 分享。

初次离屏截图暴露出顶部控制条遮挡短字幕首行的问题，因此改为底部控制条和固定阅读留白；控件淡入/淡出不改变字幕布局。最小高度提高到 144pt，旧的更小高度在加载时修正，避免快捷控制压缩可读空间。字号等其余用户偏好保留。

- `build/reader-controls-core-tests-final.log`：273 个测试体、0 失败断言。新增闲置隐藏/操作期间保留、空闲改来源不录音不丢历史、重复/忙碌请求防抖、中途停止取消恢复、最小高度检查。依旧是 CLT 顺序断言适配器，不是原生 XCTest 全量运行。
- `build/reader-controls-app-build-final.log` / `build/reader-controls-signature-final.log`：构建和本机签名记录。
- `build/reader-controls-preview-final.log`：显式合成预览，620pt / 300pt 宽窗，操作态与闲置态离屏截图，保存在 `build/reader-controls-preview-1.4/`；没有真实录音、联网分享或覆盖用户偏好。最终画面已人工检查，普通状态下底部控制条未覆盖合成字幕，闲置时已消失。
- `build/reader-controls-privacy-check-final.log`：独立翻译和零可见窗口的既有隐私检查。
- 最终截图与上述日志是布局/逻辑证据，**不是**真实系统音频→麦克风切换、首次多语模型下载、权限弹窗、VoiceOver/键盘全流程验收。特别是实际切换的中断时间尚未测量。
- 开发阶段保留正在运行的旧版；在用户明确回复“更新吧”之后，已使用 `scripts/install-local.sh` 安装并启动 1.4.0（14）。严格签名验证通过，原 1.2.1 保留为 `/Applications/StreamTranslate.app.previous`。见 `build/install-1.4.0.log`。未自动开始录音或启用未加密网页分享。
- 后续 1.4.1（15）修复了透明外边框穿透鼠标事件、手机连接窗口被字幕窗遮挡的问题，并已替换安装。旧 1.4.0 现保留为 `.app.previous`，更早备份已归档。增加真实系统鼠标事件回归，不再仅以窗口存在或内部尺寸计算正确作为验收。见 `window-interaction-fix-2026-09-06.md`。

下一轮产品范围：设置页信息组织和中文一致性、首次启动的任务引导、真实使用中的快捷操作反馈与辅助功能验收。先验证本轮最常用操作闭环，不宣称整个产品重设计已完成。

## 参考与设计推论

QuickTime 的控制随指针出现，提供了成熟的“内容优先、操作按需可见”范式：[Apple 使用说明](https://support.apple.com/guide/quicktime-player/open-and-play-a-file-qtp6cee0761b/mac)。苹果视频规范强调预期一致的播放控制：[Playing video](https://developer.apple.com/design/human-interface-guidelines/playing-video)。NN/g 的[渐进披露](https://www.nngroup.com/articles/progressive-disclosure/)与[识别优于回忆](https://www.nngroup.com/articles/recognition-and-recall/)支持把高频项目放在当前任务附近、将复杂选项延后。将这些原则用于字幕工具是本项目的设计推论，不是宣称做法已通过用户研究。
