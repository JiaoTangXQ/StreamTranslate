# 长会话字幕与历史记录 · 1.6.1

本次限制实时字幕的布局和缓存规模，新增跨重启的文字记录，并修复已确认的原生识别生命周期缺口。用户报告的长时间运行后不再出新字幕，尚未通过真实持续语音复现，不能宣称已经解决。

## 字幕与记录

- 实时缓存最多保留 100 条完成字幕。悬浮窗有流式字幕时显示最近 99 条完成字幕及当前一句，总数最多 100 条；没有流式字幕时显示最近 100 条。
- 完成字幕及后续译文、原文复核和译文修订按同一字幕 UUID 保存。字幕移出实时缓存后，待完成任务仍能更新所属会话的记录；新录音不会把旧字幕的迟到更新写入新会话。
- 文字记录位于 `~/Library/Application Support/StreamTranslate/TranscriptHistory/`，按录音会话保存，重启后仍可查看。这里不保存音频；记录随新版本开始，不从旧诊断文件导入。
- 悬浮窗时钟按钮和菜单中的 **查看历史记录…** 打开原生深色历史窗口。左侧选择会话，右侧查看完整文字；只读取当前所选会话，更新合并等待 300 ms，其他会话的修订不会重新读取当前文字。
- **清空全部记录** 一次删除该文字归档并清空当前字幕，取消旧字幕的待处理更新；后续新字幕继续保存。`~/Library/Logs/StreamTranslate/` 下的诊断资料单独保留。

写入和删除在后台串行队列执行，窗口读取时把同一 UUID 的修订合成最新一句。损坏的会话索引会显示警告，其他有效会话仍可查看；写入中断留下的不完整末行不会阻止读取此前完整字幕。文字归档没有自动保留期限，清空前会继续占用磁盘；查看某个会话仍需读取该会话的完整文字。

## 诊断结论与边界

| 证据 | 能支持的结论 |
| --- | --- |
| 原版注入 3,000 条字幕时，窗口尺寸变更 p95 为 75.1 ms | 未限制的实时字幕列表会增加布局成本。此测试不运行识别模型。 |
| 限制并修复尺寸跟随后，两轮测得尺寸变更 p95 为 8.7 ms / 21.0 ms | 列表限制降低了该合成测试的布局成本；受机器负载和布局时序影响，这些测量不是端到端字幕延迟。 |
| 同次启动中跨多次收音重启，进程物理内存占用约从 30 MB 增至 265 MB | 停止收音没有清除历史界面的资源；仅凭这个趋势不能确定模型内存泄漏。 |
| 一段约六分钟没有字幕输出的日志尾部，其输入全程静音 | 该片段不能证明识别在持续语音中停顿。真实无新字幕问题仍需带有效语音的复现证据。 |

已确认并修复的生命周期缺口：结果流报错或正常结束时，连续音频输入可能仍保持打开，导致界面继续显示运行。现在结果流的错误和正常 EOF 会向消费者传播，结束对应收音并更新界面；旧一代的结束回调不能停止新一代收音。正常点击停止仍关闭输入、等待该代最终识别结果和排队译文，再完成会话。

这些修复覆盖可验证的状态错误；合成字幕测试和模拟结果流测试均不能替代数小时真实语音识别、设备切换及实际窗口拖动验收。

## 复现布局与预览

在项目根目录执行：

```sh
python3 Tools/build_local_tool.py Tools/CaptionInteractionBenchmark.swift \
  build/interaction-bench/CaptionInteractionBenchmark
build/interaction-bench/CaptionInteractionBenchmark 3000 \
  build/history-preview-final
```

工具将合成的 3,000 条双语字幕送入当前生产视图，输出初始布局、尺寸变更和悬停的毫秒数据。悬浮窗显示仍受 100 条限制；该工具直接注入测试数据，不用于证明生产缓存的写入上限。输出目录含 `floating-620.png`、`floating-300.png`、`history-820.png`、`history-640.png` 和 `history-empty.png`。预览还检查缩放后最新一句是否可见。

夹具使用隔离偏好和临时历史目录，不录音、不加载模型、不读取真实录音，也不写入用户的字幕归档。尺寸变更由程序发起；此结果不等同于真实 WindowServer 鼠标拖动测试。
